Lesson: P2-02 - constructor property promotion と readonly

## Today I learned

- constructor の引数に visibility を付けると、property 定義と代入を省略できる
- constructor property promotion は「短く書く」だけでなく、constructor と property の対応を読みやすくする
- `readonly` は「初期化後の再代入を禁止する」ための機能
- `trackingNumber` のような識別子は、一度決まった後に変わるべきではないので `readonly` が向いている
- `readonly` を使うと、「変えてはいけない値」をコード上で表現できる

## Still unclear

- `readonly` class を使う場面はどこか
- LaravelのModelやDTOで `readonly` をどこまで使うのが自然か

## Differences from Go / TypeScript

- Goのstruct fieldには `readonly` のような機能はなく、慣習や設計で不変を守ることが多い
- TypeScriptの `readonly` に似ているが、PHPは実行時にも再代入を止める
