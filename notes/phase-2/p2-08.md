## Today I learned

- `DateTimeImmutable` は immutable な日時オブジェクトで、`modify()` しても元のインスタンスは変わらない
- `DateTime` は mutable なので、`modify()` すると元のインスタンス自体が変化する
- そのため、配送日時や配達完了日時のような「事実として記録したい時刻」は `DateTimeImmutable` の方が扱いやすい
- 関数の引数と戻り値に `DateTimeImmutable` を使うと、日時計算で元データを壊しにくい

## Differences from Go / TypeScript

- Go の `time.Time` も値を返して扱う感覚が近く、mutable object を直接書き換える感覚とは違う
- TypeScript では `Date` が mutable なので、今回の `DateTime` 側の危険さに近い
